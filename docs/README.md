# 文档索引

这个仓库的文档只解决三件事：**这东西是什么**（README）、**做到哪了**（ROADMAP）、**跟原版差在哪**（UI 基准）。其余是证据与历史存档，不重复叙述。

## 一页地图

| 文件 | 内容 | 什么时候看 |
|---|---|---|
| [`../README.md`](../README.md) | 项目介绍、截图、功能清单、与原版差距、构建与测试、许可 | 第一次来 / 想跑起来 |
| [`ROADMAP.md`](ROADMAP.md) | **唯一进度权威**：功能矩阵、M1~M10 + UI 迁移逐项验收判据与状态、风险、已付学费、版本约定 | 决定下一步做什么 / 查某项是否验过 |
| [`screenshots/`](screenshots/) | 真机截图（README 引用），命名 `NN-页面.jpeg` | 写文档、对齐视觉时引用 |
| `../ui-ref/MIGRATION-BASELINE.md`（**仓库外**） | UI 基准：原版平板截图的逐像素采样 + 源码常量双证，逐页写清尺寸/色值/结构 | 改任何页面样式之前 |
| `../evidence/`（**仓库外**） | 真机取证归档（153 项：截图、dumpLayout、日志），按里程碑命名 | 验证「这个结论凭什么这么说」 |
| `../docs/archive/`（**仓库外**） | 2026-10-19 的历史文档（计划、调研、夜间日志、当时的 prompt） | 考古用，**不作为当前结论** |

> 仓库内的 `evidence/` 只放**需要随代码一起可追溯**的少量关键截图（README 与提交说明会引用）；
> 完整取证在工作区的 `../evidence/`，不随仓库分发（体积原因）。

## ROADMAP 怎么读

文档开头 §0 有完整说明，最短路径：

1. **§3 功能矩阵** —— Android 每项能力 × 鸿蒙状态，先看有没有你要的功能；
2. **§4 TODO 表** —— 每个里程碑一行，`状态` 列写清是「✅ 真机验过」还是「🔄 只完成逻辑层」；
3. **§7 已付学费** —— 踩过的坑，动手前扫一眼能省一轮（例如 403 被误判成 401、ForEach 用索引当键复用组件）；
4. **§8 版本管理** —— 号段 `alpha.N`、tag `h-v*`、什么情况 bump。

判据一律写成**可证伪**的句子（「切学期后门数 14 → 19」而不是「切学期正常」）。
如果某行只有「代码完成」四个字，就说明**它没被真机验证过**，别当成已完成。

## 更新约定

| 你改了什么 | 必须同步更新 |
|---|---|
| 页面样式 / 布局 | `../ui-ref/MIGRATION-BASELINE.md` 对应小节（色值、尺寸、结构）+ 真机截图进 `../evidence/` |
| 完成一个里程碑 | `ROADMAP.md` 对应行的状态与证据路径（写清哪张图、哪个提交） |
| 新增/改动构建、测试方式 | `../README.md` 的「构建」「测试」两节 |
| 修掉一个反复出现的问题 | `ROADMAP.md` §7「已付学费」 |
| 改了功能边界（做什么 / 不做什么） | `ROADMAP.md` §1.2 不做清单 + `../README.md` 功能表 |
| 新增一个离线测试套件 | `tools/run-tests.sh` 的 `suites` 列表（**漏登记 = 永远不跑**）+ `../README.md` 测试节的套件/断言数 |

## 几条容易踩的分层约定

| 层 | 目录 | 能依赖什么 | 为什么这样切 |
|---|---|---|---|
| 纯逻辑 | `corelogic/` | 只能依赖其它纯逻辑（**不许 import `@kit.*`**） | 裸 Node 能直接 import 真函数跑断言；`data/` 依赖 `Prefs` → `@kit.ArkData`，测不了 |
| 存储 | `data/` | `Prefs` / 系统能力 | 只做「读 → 解码 → 写」，编解码在纯逻辑里（如 `ScoreStoreLogic`） |
| 网络 | `service/` | `rcp` / `@kit.*` | 只做 I/O，**判断交给纯逻辑**（如 `ScoreFlowLogic.decide`） |
| 页面 | `pages/` | 以上全部 + ArkUI | 取色只能走 `gridTokens()`；`@State` 不存颜色；计算写方法不写进 `build()` |

## 不写什么

- **不写推论**：没验证过的结论标「未验」，不写「应该没问题」。
- **不写两遍**：同一事实只在一个地方出现，其他文档引用它，避免分叉。
- **不写无主语的数字**：「2509 条断言」要能对应到 `bash tools/run-tests.sh` 的实际输出。
