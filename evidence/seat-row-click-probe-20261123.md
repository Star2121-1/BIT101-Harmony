# 座位行点击不触发 — 调查报告（2026-11-23 01:00~01:20）

## 现象
真机 alpha.37/38：座位列表加载正常（绿点 + "点我预约"），但点座位行不弹「确认预约该座位？」提示条。
验证 3（签到提示真机展示）因此卡住。

## 方法：代码探针（一锤定音）
临时在 `SeatPage.seatRow` 的 onClick 首行加可见状态：
```
this.reserveResult = 'PROBE:click ' + s.no + ' free=' + isFree(s.status) + ...
```
升 versionCode 38-probe 编译装机（HAP 内确认含 "PROBE:click" 1 处）。

## 结果
- 多次点击座位行（深链页 + 底栏页、多个 x/y 坐标、多个滚动位置），**PROBE 文字从未出现在 UI 树**（dump 全文搜索无命中）。
- 对比：同页面「五层」「5层中厅」chip 的点击**成功**（选区域生效、座位列表加载）。
- ⇒ **onClick 根本没被调用**，不是条件拦截（`isFree`/`reserveTarget`/`reserveBusy` 都正确），也不是 App 逻辑 bug。

## 排除项
- ✅ 点击坐标系：五层/区域点击成功，证明 dump 坐标 = 点击坐标（无整体偏移）。
- ✅ 探针确实编译进 HAP（grep 命中）。
- ✅ isFree 判据：`status===AVAILABLE`，绿点色 `#4CAF50`=AVAILABLE，一致。
- ✅ 前台焦点：多次截图确认 App 在前台（曾被游戏自动抢焦点，已重拉）。
- ✅ 不是确认条渲染在长列表下方看不到：dump 全文 49/50 节点无 PROBE、无"确认预约"。

## 结论（诚实边界）
判定为 **`uitest uiInput click` 对 Scroll 内 ForEach 子项的注入局限**（或该设备无障碍点击与 Scroll 命中冲突），
**非 App 逻辑缺陷**：onClick 已正确绑定、条件正确、探针证明只是没被调用。
- 用户**手动触摸**大概率正常，但 agent 无法替用户手点 ⇒ **真机人工确认仍欠**。
- 未执行任何预约（confirmReserve 从未走到），对外副作用红线守住。

## 处理
- 探针代码已还原（正式版 v39），无调试代码残留。
- 签到提示的**逻辑正确性**由单测保证：`signInHintFor` 28 断言 + UI 接线 3 守卫，均拆红验过；编译通过。
- 待用户手点座位行确认：若手点能弹确认条并看到"60分钟/9:00"文案，则验证 3 完成；若手点也不弹，才是真 bug，需另修 hitTest。
